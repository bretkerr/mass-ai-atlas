A founder says what they need. The Mass AI Atlas answers with a receipt: who's on the list, the month a person last checked each one, and what to doubt. Doubt is shown, never hidden.

The problem, in this morning's numbers

  • 87 of 197 pins are a neighbourhood, not an address, and looked exactly like real ones (Probe 1).
  • Only 13 of 61 funders state a check size (Probe 4), yet a founder sees a list with no caveat.
  • 52 entries were last checked in June (Probe 5); only 5 sit west of Worcester (Probe 6).

What we built (one HTML file, no build step)

  1. Ask in a sentence. “I need ___”, typed or spoken. Plain keyword rules set the Atlas's own I need… filters, which stay visible and editable. It never names an organization.
  2. Get a receipt. The five surest matches, what each offers, the month a person checked it, and a ⚠ “trust less” line only where the data gives a reason.
  3. Compare the top two. One click, one sentence: “Trust X less: …”. This is the hand-off test.
  4. Probe 1 made visible. Approximate pins are dashed rings; exact ones stay solid. Map tiles flip to their receipt.
  5. Review proposals. Drop a file of proposed entries; six checks flag duplicates, wrong places, out-of-state, closed, unsourced facts and suspicious domains, each with a reason.

What it refuses to do

  • Hide or delete an entry for doubt. Flag, never delete.
  • Sort funders by a check size most don't state.
  • Name an organization from the founder's words.
  • Call a proposal clean when its site wasn't checked: “Nothing flagged · site not checked.”

Why it can merge on Monday

Built inside the Atlas's own index.html: no build step, framework, database or key. Every number is computed in the browser from the YAML the Atlas already loads. All 32 of the repo's browser and accessibility tests pass; the data loader is vendored so it works on bad wifi.
